## Hypothesis
C-017 (knowledge/claims.md): a generator we write reproduces the public 430-qubit chemistry build's cost within 1% on the unmodified `verify.py`. The targets are exp-006's two measured builds: heliosli v10 (R8/B143/C62, cost 347,361,566) and heliosli v11 (R8/B143/C60, cost 341,914,455). The generator is a licensed port of SomeJoint's public dfthcsos pipeline or our own re-implementation.

## Source and licence (found before pre-registration; details in `external/SOURCES.md`)
- **What is public.** SomeJoint's notebook v18 ("22.67 Local GM: Full-XOR Chem", `somejoint/quantum-circuits-22-77-local-gm-889-qubit-dqi`, id 140675727) embeds the build of its team's final chemistry, block `team-b143-c60-xor2`:
  - `build.py` and five modules: the full-XOR emitter `exp/full_xor/emitter.py`, and `playbook/exp/staged_b154/{paired_anf, planio, scheduler, validation_helpers}.py`.
  - Its two data files are in the dataset `somejoint/qcc-our-chemistry-b143-c60-xor2` v1: `submission.npz` (`aef36d39…`, the factorization U, W, H2_I, H1_I, Hsym_lower, angle_words, tree_edges, brot) and `BUILD.json` (`5e28b8fe…`, each circuit's frozen product plan and schedule).
  - `build.py` emits the 15 `angle_k` circuits from the plans, checks each against its recorded SHA-256 and a 64-random-word XOR test, and **copies** `submission.npz`.
- **Licence: Apache-2.0**, stated for the notebook code (embedded LICENSE, SPDX header in `build.py`, credits cell) and for the dataset (Kaggle licence field `apache-2.0`, and "Licence: Apache 2.0." in its description).
- **What is not public.** No public notebook or dataset found holds code that produces this factorization (B154 → B143 pruning, rank 60, 8-bit requantization with coded low bits, the weight fit and gauge). The same is true of every other public build of this family: Dmitrii Gluzdov's, kirilltym's, Ahmed Berat Özer's and heliosli's builds all start from a frozen `submission.npz`. Atakan Aldemir's source bank does contain weight-training and gauge scripts. But its licence file asserts no licence for its own files ("No blanket Apache-2.0 licence is asserted"), so it is not ported.
- **Relation to the targets.**
  - SomeJoint's `submission.npz` is byte-identical to heliosli v11's (exp-006). heliosli's CREDITS say v11 takes "the factorization file byte for byte".
  - Five of the 15 circuit hashes in BUILD.json (k = 5, 7, 9, 11, 13) equal v11's files. In v11 the other ten are heliosli's promise-relying loaders.
  - So this build is v11 with SomeJoint's own ten full-XOR circuits in place of heliosli's.
  - It shares nothing with v10 (R8/B143/C62).
- **Design lineage, as SomeJoint states it.** The team "worked from clean descriptions, methods and numbers without code" of public designs by Michael Rustad, Ahmed Berat Özer, Akmal Xodarev (busyaprime), Vladislav Lavrentev (lightningv08), mrmeows and heliosli (v18 credits cell). No unlicensed code is named in this lineage.

### Scope against the lead's goal
The lead's goal is a generator for the full chemistry pipeline: factorization, gauge/Λ tuning, the submission.npz arrays and the 15 loaders. This experiment can deliver only part of it.
- **Ported and regenerated by code:** the 15 `angle_k` loaders, emitted from SomeJoint's frozen plans.
- **Taken as licensed data, not regenerated:** `submission.npz` and the plans themselves. The npz is hash-pinned, Apache-2.0, from SomeJoint's dataset. The plan search that produced the plans is not public.

C-017 is a claim about cost, so this tests C-017 as written. It does not give us a factorization generator. That gap is a finding of step 1, reported to the lead. A long gauge search was not needed and was not started.

## Prediction
Written before any build or verify. The ported code has not run anywhere.

1. **Bytes.**
   - Each of the 15 circuits the port emits with PyPI kickmix 1.0.0 on a Kaggle CPU kernel is byte-identical to its `circuit_sha256` in BUILD.json (confidence about 90%; exp-008 and exp-011 found PyPI kickmix 1.0.0 byte-identical to upstream builds). The launcher stops on any mismatch, as `build.py` does.
   - So k = 5, 7, 9, 11, 13 equal heliosli v11's files, and the other ten differ from v11. No circuit equals any of v10's.
   - `submission.npz` is byte-identical to `aef36d39…` (= v11's). This is certain, because it is a copy.
   - `submission_sha256` = `c88f058e…a414`, the digest v18 states.
2. **Per circuit (static, from BUILD.json).**
   - k = 0..3: T 305, Q 126.
   - k = 4, 6, 8, 10, 12, 14: T 283, Q 128.
   - k = 5, 7, 9, 11, 13: T 260, Q 128.
   - 4,218 per pass. All 15 pass both the build's own 64-random-word XOR check and our exp-006 `xor_oracle_check.py` in all three modes (zero, sign, random), with fail fraction 0. These are full-XOR loaders, unlike v10's and ten of v11's.
3. **Official verify, default salt.** Exact if the bytes match.
   - PASS, verified_shots 78,080.
   - T_total **16,366** = ANGLES 8,436 (2 × 4,218) + outer 369 + inner 5,311 + Givens 2,250. The heuristic part is 7,930, the same as v11. ANGLE share 51.55%.
   - Q **430** = persistent 126 + temporary 304. Angles temporary 77, max width 128.
   - The factorization and words are those of v11, so the metrics equal exp-006's v11 run:
     - lambda_eff **48.76425214813735**;
     - Lambda 305.66265;
     - E_gap 3.9149022;
     - error_1 15.830 mHa, error_2 19.9988 mHa.

     Cross-platform float differences of 1 to 2 ulp are possible (exp-001), so the tolerance is 1e-12 relative.
   - Cost **343,172,572.78** (± 1e-9 relative), the figure v18 states.
4. **Fresh salt `exp012-a`.**
   - Everything identical to the default run except the seed: the same T, Q, lambda_eff and cost. In exp-006, T had no conditioned gates and the metrics were deterministic in the factorization.
   - If the salt changes any reported metric, that is a failed prediction. It is not necessarily a refutation.
5. **Against the targets.**
   - v11: 343,172,573 / 341,914,455 = **1.00368, so +0.37%**, inside ±1%.
   - v10: 0.98794, so −1.21%. That is outside v10's ±1% window but cheaper than v10.
   - The cost is higher than v11 because ten full-XOR circuits cost 4,218 per pass against heliosli's 4,188 promise-relying ones (+60 Toffoli both passes, +0.37%).
6. **Score impact** if it holds: the dfthcsos improvement factor over the reference (3,355,599,588.32, exp-002) is **9.7782**, ×2.1384 on the three-task score. This is the ported circuit's factor, not anything of ours.
7. **Resources.**
   - Build: about 3 s of emission (the README says so) plus the XOR checks, under 2 min and under 2 GB in total.
   - Each verify: 30 to 45 s, about 0.75 to 0.9 GB (exp-006: 29.5 to 42.8 s, 0.73 to 0.86 GB).

**Refutation rule (fixed now).** C-017 is refuted by this experiment if either verify run reports FAIL, or reports a cost outside both ±1% windows. The windows are v11 [338,495,311, 345,333,600] and v10 [343,887,950, 350,835,182]. Together they span [338,495,311, 350,835,182].
- A byte mismatch alone doesn't refute C-017. It would be reported as a failed prediction 1, and the launcher would stop before verifying, so the experiment would be inconclusive.
- Holding C-017 this way does **not** show we can regenerate the factorization (see Scope).

## Method
- **Baselines.**
  - exp-006 (accepted): v10 cost 347,361,566; v11 cost 341,914,455 with lambda_eff 48.76425214813735, T 16,306, Q 430, and the same `submission.npz`. It also supplies the independent XOR-oracle check `experiments/exp-006/xor_oracle_check.py`.
  - exp-002 (accepted): `src/angleload`, the official ANGLE_k loader port, and the reference cost.
  - exp-011: the model for the port, review and kernel.
- **Port: `src/chem/`.**
  - `src/chem/b143_c60_xor2/` holds v18's `blocks/dfthcsos/team-b143-c60-xor2/source/` files verbatim, with unchanged bytes and the upstream layout: `build.py` (kept for reference, never run), `README.md`, `source_sha256.json`, `exp/full_xor/emitter.py`, and `playbook/exp/staged_b154/*.py`.
  - The upstream modules resolve `staged_b154` through `sys.path` entries relative to their own files, so the layout must stay.
  - Our files:
    - `LICENSE` (the upstream Apache-2.0 text);
    - `NOTICE` (author, source, version, lineage, the missing-factorization-generator caveat, our modifications, what is whose);
    - `MANIFEST.json` (SHA-256 of every ported file, plus the two pinned data files and their dataset);
    - `.gitattributes` (`-text`, so checkouts stay byte-identical);
    - `generate.py`, our launcher.
  - The launcher re-implements `build.py` with these changes:
    - explicit `--data`, `--verifiers` and `--out` paths, because `build.py` locates the verifiers beside a competition `kickmix.so` and PyPI kickmix has no such neighbour;
    - a manifest check of every ported file and both data files before anything is imported;
    - a JSON build record: per-circuit T, Q and SHA-256, seconds, and the modules imported during the build.

    It keeps every check of `build.py`: the delta hash, the plan audit, the frozen circuit SHA-256, the metadata, the 64-random-word XOR test, word recovery and the submission digest.
  - The data files are not committed (`*.npz` is gitignored, and BUILD.json is a 465 KB third-party file). The kernel takes them from the attached dataset and checks them by SHA-256.
- **Static review before the first run.** `tools/static_review_run.py` → `static_review_run.json`. It is a parse-only AST review of every `.py` file the kernel will run: the 5 upstream modules, `build.py` (listed but not run), our launcher, the kernel template and `xor_oracle_check.py`. It covers five categories: imports, file writes, network, subprocess and dynamic loading. It also resolves bare-name imports.
- **Kaggle only.** Per the 2026-10-29 user decision, nothing under `src/chem/b143_c60_xor2/` is imported or run locally. Locally we only parse files (`ast`) and hash them.
- **Kaggle kernel** `rainm4/exp-012-chem-xor2-port-verify`. It is a private CPU script kernel, with internet on, `pip install kickmix==1.0.0` pinned, the competition source attached, and `dataset_sources: [somejoint/qcc-our-chemistry-b143-c60-xor2]`.
  - `src/chem` and `xor_oracle_check.py` ship inside the script as a base64 zip with per-member SHA-256 (`src/tools/build_kernel.py`).
  - Each step runs as a child process, with memory sampled by the parent:
    1. `unpack`: decode and hash-check the zip.
    2. `build`: `python -I -B src/chem/generate.py --data <dataset dir> --verifiers <competition verifiers> --out /tmp/exp012/dfthcsos`.
    3. `stats`: kickmix-load each circuit, record Q, `operation_statistics()` and the file SHA-256, and compare with BUILD.json and with heliosli v10/v11's manifest hashes (embedded from exp-006's local manifests).
    4. `xor_check`: our `xor_oracle_check.py` at 8 shots per address, in zero, sign and random modes.
    5. `verify_default`: `python -I dfthcsos/verify.py /tmp/exp012/dfthcsos`, cwd the competition `verifiers/`, `PYTHONDONTWRITEBYTECODE=1`. This is the unmodified official verifier.
    6. `verify_salt`: the same with `--salt exp012-a`.
  - The built circuits stay in `/tmp`. Only JSON records and logs are written to the kernel output.
  - The kernel never calls a Kaggle API and never submits.
- **Results.** `src/tools/make_results.py` with `make_results.json` writes `results.json` from the downloaded verifier JSON, build and stats records. Verifier stdout from both runs goes to `verifier.log`.
- **Salts.** The default and `exp012-a` (the lead's instruction).
